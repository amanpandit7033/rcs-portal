Getting startedAuthentication

Send your secret key in the apikey header on every request to a private endpoint. X-API-Key and Authorization: Bearer <key> work too.

Keys start with rcs_. A raw key is shown once when you create it and is stored as a SHA-256 hash.

To restrict a key to specific source IPs, add them in Settings. Requests from other IPs return HTTP 401.

Getting startedRate limits

Requests are throttled per tenant. The default is 120 requests per minute. Administrators can raise it for higher throughput.

HTTP 429 means you went over the limit. The response carries error code "throttled". Retry with exponential backoff.

Getting startedIdempotency-Key

Add a unique Idempotency-Key header so a retry after a network timeout never sends twice or debits twice.

When you send the header:
  • The first successful response (200–299) is cached for 24 hours.
  • Repeat requests return the cached response with X-Idempotency-Status: HIT.
  • No extra wallet debit and no duplicate message record is created.

POST/api/v1/messages/send/

Send to one recipient or up to 100

Adds one or more messages to the sending queue. The returned message IDs are our internal UUIDs.

FieldTypeRequired
sender_profile_idintegerYes
message_typestringYes
content_typestringNo
recipientstringOptional*
recipientsarray[str]Optional*
template_idintegerOptional
custom_paramsobjectOptional
custref1 .. custref6stringOptional

Field details

  • sender_profile_id: ID of the carrier-registered bot or sender profile.
  • message_type: "PROMOTIONAL", "TRANSACTIONAL" or "OTP".
  • content_type: "text", "rich_card", "carousel" or "template" (default).
  • recipient: phone number, 10 digits or E.164 (+91). *Required if recipients is omitted.
  • recipients: up to 100 numbers for a broadcast.
  • template_id: approved template ID, used with content_type="template".
  • custom_params: values for template placeholders, e.g. {"name": "Aman", "order_id": "9921"}.
  • custref1 to custref6: your own tracking references, up to 100 characters each.
Request
curl -X POST "{{ base_url }}/api/v1/messages/send/" \
  -H "Content-Type: application/json" \
  -H "apikey: YOUR_API_KEY" \
  -H "Idempotency-Key: req_981240124" \
  -d '{
    "sender_profile_id": 1,
    "recipient": "9876543210",
    "message_type": "TRANSACTIONAL",
    "content_type": "template",
    "template_id": 12,
    "custom_params": {
      "name": "Aman",
      "order_id": "APX-98214"
    },
    "custref1": "ORDER_DISPATCH_98214"
  }'

WebhooksDelivery report callbacks

When a carrier delivers or reads your message, we send the event to your callback URL as an HTTP POST. Each call is signed with HMAC-SHA256 in the X-Signature-SHA256 header.

Example POST payload
{
  "event": "message.dlr",
  "id": "e7b2354c-b71a-4d43-982c-4731d1b32f50", // your internal message UUID
  "recipient": "9876543210",
  "status": "delivered", // delivered | read | failed
  "failure_reason": "",
  "delivered_at": "2026-10-06T10:45:04.000Z",
  "read_at": "2026-10-06T10:45:12.000Z",
  "timestamp": "2026-10-06T10:45:04.120Z"
}

Verify the signature

Compute the HMAC-SHA256 of the raw request body with your secret, then compare it to the header using a constant-time check. Reject the request if they differ.

import hmac
import hashlib

def verify_webhook_signature(raw_request_body_bytes: bytes, incoming_header_sig: str, secret: str) -> bool:
    expected_sig = hmac.new(
        secret.encode("utf-8"),
        raw_request_body_bytes,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected_sig, incoming_header_sig)
const crypto = require("crypto");

function verifyWebhookSignature(rawBodyBuffer, incomingSignature, secret) {
  const expectedSignature = crypto
    .createHmac("sha256", secret)
    .update(rawBodyBuffer)
    .digest("hex");
  return crypto.timingSafeEqual(
    Buffer.from(expectedSignature),
    Buffer.from(incomingSignature)
  );
}
function verifyWebhookSignature($rawRequestBody, $incomingSignature, $secret) {
    $expectedSignature = hash_hmac("sha256", $rawRequestBody, $secret);
    return hash_equals($expectedSignature, $incomingSignature);
}
